⚠️ Credential File Ownership (critical):
The OpenClaw gateway process runs as user `node` (via `runuser -u node` in the
container entrypoint). Any subprocess the gateway spawns (cron job pipeline,
openclaw-morning-context, gws-personal, gws-rental) inherits the `node` UID.

When deploying credentials via `docker cp` or `scp` + `docker cp`, files arrive
as root:root with 600 permissions. The `node` user cannot read them.

After every credential deployment, run:
  chown node:node /data/openclaw-gws/config/credentials.json
  chown node:node /data/openclaw-gws/config/rental-credentials.json

Manual `docker exec` commands mask this because docker exec defaults to root.
The symptom is: manual gws calls succeed, but cron/morning-brief pipeline fails
with "command_error" / exit status 1 for GWS calls.

🔵 PLAN DELTA — Updated Architecture + Execution Strategy (March 2026)
Purpose

Document how the original OpenClaw + Google Workspace rollout plan was modified during real implementation.

The original design was architecturally correct.
However, execution sequencing and operational hardening were adjusted to reduce risk and stabilize the system.

✅ Major Changes from Original Plan
1. Execution Order Changed — Stabilize One Account First

Original plan:

Build full dual-account architecture immediately

Actual implementation:

Stabilized single-account runtime first, then added rental

2. Runtime Storage Path Changed — Persistence Requirement

New standard runtime root:

/data/openclaw-gws

Structure:

/data/openclaw-gws/bin
/data/openclaw-gws/config
/data/openclaw-gws/output

3. Headless Auth Flow Clarified

Proven flow:

Authenticate on Mac → Export authorized credentials → Copy to VPS → Wrapper points to file

4. Wrapper Strategy Simplified — Smaller Components First

Build small persistent scripts, refactor into larger wrappers later if needed.

5. Morning Brief / Agent Wiring Split from GWS Infrastructure

Infrastructure stabilization must precede orchestration logic.

✅ Architectural Principles That Remain Correct

Subagents should not be used as authentication isolation boundaries

Separate wrapper scripts must be used for separate Google accounts

Personal Google Tasks should remain the master task system

Rental calendar should remain read-only

Draft-first email workflows are safer than auto-send

Heartbeat / cron automation should be added only after manual validation

Rental path uses direct account auth, not delegated Gmail API access

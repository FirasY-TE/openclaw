===== PHASE 1 FORUM TOPIC ROUTING CHECKLIST (OPERATOR) =====

Goal: move operational delivery from DM-only targets to forum-topic routes with deterministic fallback.

1) Create Telegram Forum supergroup and enable Topics.
2) Create topics: Urgent, Triage Digest, Beeper, Hospitable, System/Auth.
3) Add the bot to the forum and confirm it can post in all topics.
4) Capture topic IDs for each topic and record them in your VPS ops notes.
5) Set route target env vars on VPS using topic-capable format `<chatId>:topic:<topicId>`:
   - `ROUTE_TRIAGE_DIGEST_TARGET` (morning brief + evening reset primary route)
   - `ROUTE_SYSTEM_AUTH_TARGET` (auth health degraded alerts primary route)
   - `ROUTE_URGENT_TARGET`
   - `ROUTE_BEEPER_TARGET`
   - `ROUTE_HOSPITABLE_TARGET`
6) Verify route values and container health:
   - `ssh openclaw-vps "docker exec openclaw-ridl-openclaw-1 env | rg 'ROUTE_(TRIAGE_DIGEST|SYSTEM_AUTH|URGENT|BEEPER|HOSPITABLE)_TARGET'"`
   - `ssh openclaw-vps "docker exec openclaw-ridl-openclaw-1 openclaw channels status --probe"`
7) Validate `triage_digest` delivery path (morning brief + evening reset):
   - `ssh openclaw-vps "docker exec openclaw-ridl-openclaw-1 openclaw cron run ce3cf461-3e58-49f0-8e64-e0b2b7b873bb --timeout 180000"`
   - `ssh openclaw-vps "docker exec openclaw-ridl-openclaw-1 openclaw cron run 742493a0-6a2b-42e4-b518-2a87961db8a4 --timeout 180000"`
8) Validate `system_auth` delivery path:
   - `ssh openclaw-vps "docker exec -u node openclaw-ridl-openclaw-1 /data/openclaw-gws/bin/openclaw-gws-auth-health-check"`
9) Validate fallback policy (retry once, then DM fallback):
   - Temporarily set an invalid topic ID in `ROUTE_SYSTEM_AUTH_TARGET`.
   - Re-run auth health check and confirm DM includes marker: `[FALLBACK from system_auth]`.
   - Restore the correct topic ID immediately after test.

Fallback policy (all topic-routed operational sends):
- Primary: forum topic route from canonical logical route map
- Retry: one retry to the same topic route
- Final fallback: DM target `telegram:1460581318` with route marker
- Full executable UAT command pack: see `docs/commands.txt` section `PHASE 1 UAT — FORUM TOPIC ROUTING`.

Appointment-to-Calendar (prompt + confirm)
5,15,25,35,45,55 * * * *
Script: /data/openclaw-gws/bin/openclaw-gws-appointment-prompt (Python)
Helper: /data/openclaw-gws/bin/openclaw-gws-appointment-confirm (Python)
Log: /data/openclaw-gws/logs/appointment-prompt.log
State: /data/openclaw-gws/state/pending-appointments.json
Flow:
  1. Reads gmail-review-summary-latest.txt for CalendarPrompt=yes entries.
  2. Fetches full email body, extracts date/time/title/location.
  3. Writes pending appointment (with full event JSON) to state file.
  4. Sends Telegram prompt: "Appointment detected: ... Would you like me to add?"
  5. Injects a one-shot main-session system event (openclaw cron add --at 1m
     --session main --system-event "..." --delete-after-run) so the gateway
     agent has context when the user replies.
  6. User replies "yes" in Telegram → main session agent sees system event
     context → agent calls: exec python3 .../openclaw-gws-appointment-confirm latest
  7. Confirm helper reads state, creates calendar event via gws-personal,
     marks appointment as confirmed.
Agent TOOLS.md (/home/node/.openclaw/workspace/TOOLS.md) documents the
confirm helper commands for the gateway agent.
Idempotent via state file (skips already-processed message IDs).

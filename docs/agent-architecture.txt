===== OPENCLAW AGENT ARCHITECTURE =====

Runtime Scope:
- VPS operational layer: /data/openclaw-gws/bin, /config, /output, /state, /logs
- Repo intelligence layer: src/phase3/* (schemas, lifecycle, signals, orchestration, subagents)
- Canonical task system: Google Tasks
- Delivery: Morning Brief via OpenClaw cron (07:00 weekdays), routed to `triage_digest` topic first with DM fallback on topic failure; no live ad hoc API calls at send time

Container User Model:
- Gateway process runs as user `node` (entrypoint uses `runuser -u node`)
- All gateway-spawned subprocesses (cron pipeline, morning-context, gws wrappers) inherit UID `node`
- `docker exec` defaults to root — masks permission issues during manual testing
- Credential files in /data/openclaw-gws/config/ MUST be owned by node:node
- After any credential deployment: chown node:node /data/openclaw-gws/config/*.json

===== CALENDAR SOURCES (openclaw-morning-context) =====

All wired sources (in the Python script):
- personal-gws: Google Calendar for personal account via gws-personal (primary + subscribed calendars)
- rental-gws: Google Calendar for rental account via gws-rental (primary calendar, today+tomorrow window)
- work: ICS file in workspace (work calendar not available via GWS)
- personal-ics: optional fallback ICS

Rental calendar events are tagged source=rental-gws and health reports as rental-gws-calendar.
Rental Gmail signal is separate — it comes from gmail-review-rental-summary (text buckets),
not the Calendar API. Booking feeds subscribed on the personal calendar (e.g. Hospitable ICS)
appear under personal-gws events.

Full reference: docs/morning-brief.txt


===== PHASE 3 HEALTH + FRESHNESS MODEL =====

- Morning Brief reads prepared context only (no live Gmail/Calendar/Hospitable/Tasks/news calls at send time)
- Hospitable degraded mode:
  - if Hospitable is stale/failing, rental Gmail pipeline continues
  - brief still generates
  - health marks Hospitable as stale/error
- Auth health degraded mode:
  - if personal or rental token expires/revokes, auth health check detects within 30 min
  - Telegram alert sent immediately (rate-limited 1/hour)
  - morning brief surfaces auth-health: error in health + topAlerts
  - pipelines continue running (may produce stale data until reauth)
  - reauth runbook: docs/commands.txt (TOKEN REFRESH RUNBOOK section)
- Freshness status is surfaced in health and topAlerts

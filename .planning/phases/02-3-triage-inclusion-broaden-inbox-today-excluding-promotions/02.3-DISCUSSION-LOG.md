## Telegram constraints (informational, no decision required)

User asked: _"I am wondering if Telegram is going to have limitations on how this data can be presented."_

Constraints surfaced to user and captured in `code_context`:

- **4096-char hard cap per message.** `send_with_topic_fallback` does not chunk. Mitigated by Phase 02.1.3 file snapshot (32 KB) reaching the agent.
- **Markdown tables do not render** in Telegram (pipes show literally). Newsletters tier renders as a fenced code block (D-15).
- **MarkdownV2 escaping** is strict.
- **Inline images / multi-part** out of scope (deferred to Phase 02.4).

These shape D-14 (first-message budget + truncation footer) and D-15 (fenced-code-block render for the noise tier).
